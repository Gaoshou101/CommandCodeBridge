# CommandCodeBridge 下一步优化规划

更新：2026-10-18。第一、二、三轮本地实现已进入 v0.2.10 未发布源码，验证证据见[验证记录](VALIDATION.md)。真实上游验收按用户要求待验证；正式发布状态以 Release 为准。

## 结论

下一阶段优先降低故障定位和升级成本，再补真实协议验收与长期运行能力。

| 优先级 | 方向 | 主要交付 | 粗估工作量 |
| --- | --- | --- | --- |
| P0 | 凭证与宿主运行登记一致性 | 只读诊断、保存与加载确认、脱敏诊断摘要 | 2–3 个开发日 |
| P0 | 插件与 CPAMP 升级兼容性 | 插件／页面／快照后端能力检查、兼容矩阵 | 2–3 个开发日 |
| P1 | 真实协议与模型可用状态 | Claude 关键路径验收、按凭证隔离的模型证据 | 2–4 个开发日，账号等待另计 |
| P1 | 数据恢复与长期运行成本 | 损坏隔离、分类落盘、统计保留与采样优化 | 3–5 个开发日，先测量 |
| P2 | 上游变更与维护效率 | 目录变化预览、契约检查、CI 与文档同步 | 逐项估算 |

## 当前基线与证据边界

- 核心功能已覆盖多凭证、模型映射、三种客户端协议、工具和图片、原生额度窗口、请求统计。
- v0.2.9 已实现最近请求同步、额度落盘、重启恢复和密钥变更隔离；旧待办中的这些事项已经完成。
- 仓库记录已有四平台 CPA v8.0.23 宿主联测、异常恢复、热升级和前端回归，以及真实免费 Ling 模型 Chat／Responses／工具往返验证。
- Claude 原生 Messages、图片、thinking signature、ZDR，以及真实个人／组织身份和同账号多 key 的共享行为，仍有真实验证缺口。
- CPAMP 页面固定基于源码 dbf61dd；完整周期快照另需 Manager Server 接受 commandcode。
- 第一轮使用项目内 Go 1.26 工具链与隔离 CPA 进行回归，结果见 VALIDATION.md；此前 PATH 缺少 Go 已不构成验证限制。
- 最初规划时 GitHub 实时查询未成功；后续已创建 [PR #12](https://github.com/Gaoshou101/CommandCodeBridge/pull/12)，三轮源码均沿用该 PR。不据此推断当前生产部署或 Release 状态。

历史记忆记录过“凭证文件存在但 CPA 运行时没有加载，最终报 auth_not_found”的现场问题。本轮在隔离 CPA 复现了插件仍持有凭证、宿主缺失登记、请求进入插件前被拒绝及恢复的链路；没有连接目标部署，不能据此认定历史现场的具体根因。

## P0-1（第一轮已实现）：凭证与宿主运行状态诊断

**收益：缩短“有 key、有模型，却没有可用账号”的定位过程。**

### 实现前依据

- GET /status 只返回插件版本、本地凭证数、模型数及持久化状态。
- GET /credentials 的健康度来自账户查询和插件已收到的请求，不能说明 CPA 是否已将凭证纳入可调度状态。
- affinity.go 中已有 runtimeAuths()，封装 host.auth.list，供删除和会话重新分配后的确认使用。
- 现有 POST /models/test 直接进入插件执行器，成功不能证明客户端经 CPA 调度同样成功。

### 第一轮已交付

1. 增加只读诊断入口，核对插件凭证、CPA 运行登记、启停状态、routing ID、模型映射和冷却状态。
2. 展示尚未登记、登记重复、路由 ID 不一致、已停用、模型未映射、已知冷却、宿主不可查询等明确结果。
3. 新增／编辑／会话重新分配后，分别反馈“保存成功”和“宿主确认”；未确认时提供可重试的结果。
4. 分开标注账户查询、插件直测、客户端经 CPA 调用三种检查；证据带来源和时间。
5. 提供脱敏诊断摘要，包含版本、数量、状态和错误类别，排除密钥、认证结果、请求正文与私人账户信息。

### 验收

- 隔离 CPA 复现遗漏登记、重复／旧 routing ID、停用未同步，以及热升级后的登记状态。
- 默认诊断不发模型生成请求；不能检查的项目显示“未知”。
- 宿主在请求进入插件前拒绝调用时，仍能从诊断定位到缺失环节。
- 恢复操作有明确动作和结果；自动恢复在宿主能力确认后另行设计。

## P0-2（第一轮已实现）：升级兼容性与功能生效检查

**收益：减少“安装成功但界面或历史功能没有生效”。**

### 实现前依据

面板检查已有进程、路径、HTTP 页面标识和摘要。升级涉及插件动态库、外部页面和 Manager Server 快照名单，单个页面摘要无法说明全部后端能力。

### 第一轮已交付

1. 扩展现有检查为能力清单：插件运行版本、实际页面版本／摘要、额度接口、最近请求接口、快照后端能力和检查时间。
2. 发布清单记录已验证的 CPA、CPAMP 源码和 Manager Server 基线，以及新增能力的最低要求。
3. 升级前显示差异、备份位置及重启要求；升级后通过实际 HTTP 页面和接口检查生效。
4. 区分页面存在、页面已对外服务、快照后端可用。无法只读确认的后端能力显示未确认，避免为检测写入用户快照。
5. CI 保留 pinned 基线，增加一个经选择的较新上游版本兼容任务；验证后再决定是否更新默认基线。
6. 保留 apply.py --check 先校验全部插入点、拒绝歧义、重复应用安全的现有约束，补充版本不匹配说明。

### 验收

覆盖仅更新插件、仅更新页面、未打快照后端补丁、浏览器缓存旧版，以及异机／容器无法自动探测等组合。检查结果准确指出下一步操作，并保留已验证的热更新和回滚行为。

## P1-1（第二轮本地已实现）：真实协议验收与模型可用状态

**收益：让支持范围和模型选择有可追踪证据。**

### 交付范围

- 扩展 tests/commandcode_live.py，按模型、套餐、客户端协议、上游协议和测试时间记录脱敏结果。
- 优先补 Claude Messages 流／非流、工具往返、图片，以及 thinking signature 返回与重放。
- ZDR 分开记录“参数／请求头正确发送”和“上游接受”；保留策略需官方依据，不能由一次请求成功推断。
- 核实真实个人／组织身份、同账号不同 key 的额度和冷却归属，补必要的脱敏字段夹具。
- 模型页区分目录可见、套餐权限未知、明确不在套餐、最近实测成功、临时限流或故障；结论按凭证版本、账号和测试时间隔离。
- 插件直测与客户端经 CPA 测试分别展示；生成检查由用户主动触发，展示 token 上限和请求范围。

### 验收

关键路径有真实客户端响应、插件日志与 CPA usage 对照；单模型权限不足不将整张凭证判失效，临时 429 不成为永久不可用标记。无法取得权限的组合明确记为待验收；真实凭证位于仓库外，真实生成不进入 CI。

## P1-2（第二轮已实现）：数据恢复、统计增长与采样效率

**收益：控制运行时间增长带来的成本，降低局部存储故障影响。**

### 第二轮实现前依据

- 请求日志有 10–10,000 条保留限制；统计按“分钟 × 模型”累计，当时未见按时间淘汰策略。
- 请求、统计和额度共用 persistDirty，每次分别写三个 JSON；单文件原子替换不提供跨文件事务或断电耐久保证。
- 启动时任一已读取的运行数据 JSON 无法解析会返回错误。
- 采样已有最多 3 个并发、每凭证请求合并、缓存和错误退避，可进一步测量同账号多 key 的重复查询成本。

### 交付范围

1. 测量长时间、多模型、多凭证下的统计条目、磁盘写入、恢复时间、内存和管理查询 P95；复用已有并发测试。
2. 请求、统计、额度设置独立变更标记，减少无关写入；展示最近成功刷盘时间和持续待写时长。
3. 设计统计保留与分层聚合，例如近期分钟级、较早小时／日级；明确查询精度、迁移和备份语义后实施。
4. 运行数据增加格式版本、损坏隔离和最后有效快照恢复；设置／凭证错误继续明确报告，恢复后展示缺失范围。
5. 真实账户身份验证后，评估按账号合并采样和增加调度抖动；身份未知时保持凭证隔离。

### 验收

- 故障注入覆盖单文件损坏、部分写入失败、强制中止和恢复；历史观察损坏不静默清空有效配置。
- 保留统计清空 epoch、关闭前刷盘、换 key 隔离、失败保留原采集时间及本地冷却跳过语义。
- 对照写入量、查询延迟和恢复耗时。是否采用 SQLite／WAL 由测量和一致性要求决定。

## 第二轮实际交付与边界（2026-10-18）

- 模型页按所选凭据展示插件直测和 CPA 请求证据；只读 `GET /models/evidence?credential_id=...` 不生成。证据绑定密钥版本、代理、上游、ZDR、账户与完整模型配置，保留日志丢失／截断或 24 小时过期后显示未知／过期。只认明确 `MODEL_NOT_IN_PLAN`；普通 403 为权限原因未知，429 为临时限流。
- `commandcode_live.py` 提供无网络 `--dry-run`、请求数与输出 token 上限、脱敏报告；覆盖 Chat／Responses／Messages 流和非流、双协议工具往返、Messages 图片与 thinking 签名重放。ZDR 分开记录请求参数／模拟端实际请求头和上游接受，保留策略仍需官方依据。
- 三类运行数据分别标脏、批量落盘，检查点最多每分钟更新一次；新增格式元数据、单文件损坏隔离、有效检查点恢复和持久恢复提示。设置／格式元数据错误仍阻止加载。统计清空防止旧检查点恢复；保留原统计副本。
- 最近 7 个完整 UTC 日加当天保留分钟级，更早按日汇总，默认永久保留日总量；自定义区间重叠日按整日纳入并提示精度。可选 1–3650 天过期；首次迁移保留旧精度副本，降级需人工选择恢复边界。
- 采样间隔增加 0–20% 正抖动，保留 3 并发、缓存、失败退避及逐凭据隔离；未启用跨 key 查询合并。
- 90 天 × 2 模型 × 每分钟一条的本地合成测量保留 259,200 个请求：统计桶 259,200 → 21,768，序列化体积 77,241,601 → 6,492,669 字节。详情及环境限制见 VALIDATION.md。
