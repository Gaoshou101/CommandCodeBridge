# 第三轮：CommandCode Studio 风格与页面优化计划

日期：2026-10-18。状态：**计划完成，待实施**。第一、二轮实现已先提交 [PR #12](https://github.com/Gaoshou101/CommandCodeBridge/pull/12)，实现基线为 `c03c314`；本计划随后以独立文档提交附到该 PR。

## 1. 目标与范围

继续模仿 CommandCode 官网控制台的美术风格和页面设计，让管理员能快速完成三件事：确认账号与额度、选择有证据的模型、定位失败请求。沿用五个导航入口，优先调整现有 HTML、CSS 和渲染函数。

- 主范围：插件控制台的概览、凭据与用量、模型映射、请求日志、设置，以及管理登录、编辑、导入、测试和确认窗口。
- CPAMP：同步验证 CommandCode 额度卡片、登录入口及内嵌控制台的展示；原生工作区继续遵循 CPAMP 自身组件与主题，不把整个宿主换成 Studio 外观。
- 本轮不扩展计费、组织管理或生产部署。第二轮真实 Claude／图片／thinking／ZDR、个人／组织和同账号多 key 验收继续为**待验证**；视觉完成不改变这些结论。

## 3. 当前界面的具体问题

基于 `c03c314` 源码及第一、二轮本机虚构数据截图：

| 位置 | 当前问题 | 本轮决策 |

| 全局 | 主按钮固定紫色，状态多使用同一种紫色 badge；5／8px 圆角与 R2/R6 方向有差异 | 统一中性主按钮、近直角边框与语义状态，紫色只用于选中／证据强调 |

| 设置页 | 请求参数、统计保留、ZDR、CPAMP 路径混在一个长表单；状态与恢复提示是连续文本 | 按任务分区，说明贴近字段，安装检查和恢复记录使用结构化行 |
| 日志页 | 桌面列表与窄屏多行结构差异较大；详情当前内联展开会推移后续请求 | 统一关键列，使用右侧详情面板；手机面板覆盖内容区，关闭后回到原请求 |

## 4. 视觉与布局约定

### 样式变量草案

| 维度 | 目标 | 依据 |
| --- | --- | --- |
| 浅色核心 | 使用 R6 的背景、文字、主按钮、弱背景、次文字和边框值 | 已测量；控制台应用效果仍需复核 |
| 深色核心 | 背景 `#000000`、区域 `#09090b`、弱区域 `#18181b`、文字 `#fafafa`、次文字 `#a1a1aa`、边框 `#27272a` | 沿用现有值并参照 R2/R4；不是当前官网暗色测量值 |
| 强调与状态 | 紫色仅强调当前选择；成功绿、待处理／限流黄、失败红、未知灰，全部配中文状态文本 | 本项目适配；对比度不达标时调整具体色值 |
| 字体 | Geist 正文；中文使用 Segoe UI／Microsoft YaHei／系统字体；Geist Mono 或 Cascadia Code 表示 ID、token、延迟 | R6 与现有环境；未核实许可前保持系统回退，不依赖远程字体 CDN |
| 字阶 | 页面标题 24/32px、分组标题 15/22px、正文与表格 14/22px、辅助文字 12/18px、指标 28/36px | 本项目可读性目标，不作为截图反推的精确值 |
| 边框与圆角 | 1px 边框；页面区域 0px，控件 2px，窗口最多 4px；状态标签统一 2px | 以 R2/R6 为主；移除嵌套卡片和不必要阴影 |
| 间距与控件 | 4／8／12／16／24／32px；桌面控件高 36px，手机主要操作触达区至少 44px | 本项目适配 |
| 页面骨架 | 展开导航 224px、收起 64px、页头 56px；主内容桌面边距 32px、手机 16px；详情宽 420–480px | 初始目标，按实际字体与 1280px 视口复核 |

实现为一套 CSS 变量，覆盖主按钮、hover、focus、选中、disabled、告警和浅深主题；不继续在渲染字符串内写颜色。保留现有主题选择，避免首次渲染闪烁。图标沿用内联 SVG，统一 18–20px 视框和线宽，图标按钮保留可访问名称。

### 信息结构

```text
导航             页头：路径                         主题 / 管理身份
概览             页面标题                 主要操作 / 范围筛选
凭据与用量       摘要与需要处理的问题
模型映射         核心列表或当前凭据额度              详情面板（按需打开）
请求日志         分页 / 原始观察时间 / 精度说明
设置
```

每页最多一个突出的主操作；“清空统计”“删除”“重新分配会话”与常规刷新分组。长 ID 可换行或截断，但提供完整查看／复制；错误详情可局部滚动，页面根节点不出现横向滚动。

## 5. 逐页交付

| 页面 | 设计与交互 | 完成标准 |
| --- | --- | --- |
| 全局与登录 | 导航、页头、状态、按钮和表单统一；明确 Bridge 管理登录身份；管理登录与 CommandCode 官网授权使用不同文案 | 键盘可遍历五页；收起导航仍有名称；主题切换和登录错误不导致布局跳动或身份混淆 |
| 运行概览 | 保留请求、token、缓存和速率四项真实指标，使用横向摘要；日期筛选并入页头下方；健康异常可跳转所选凭据；模型用量表统一数值对齐 | 未采到用量显示未知；无请求与筛选无结果分开；历史日精度与恢复缺口提示保持可见；不新增虚构成本图 |
| 凭据与用量 | 将诊断改为“异常数／待确认数／检查时间”摘要，按需展开；账号选择器紧凑化；额度优先展示余额和 5h／周／月窗口；详细证据与最近请求在同一凭据范围 | 正常时首屏见所选账号及额度；保存与宿主加载分开；账户查询、插件直测、CPA 请求三类证据分别带时间；失败保留旧额度并标原始时间；未知 cap 不画已知比例 |
| 模型映射 | 凭据选择、名称搜索和状态筛选放在一条工具栏；桌面行展示名称、上游、协议、思考、证据摘要；详情列出两类来源、时间、过期、重试信息；手机精简列表 | 搜索与筛选仅处理已取回数据，不额外生成；切凭据立即清理旧证据；403／429／未知／过期可区分；测试窗口仍说明单次最多 256 输出 tokens 及插件直测范围 |
| 请求日志 | 保留时间、模型、结果、凭据、耗时和 token；点击行打开右侧详情，分为路由／协议、时延／用量、错误；手机同一详情为全宽面板 | 焦点进入并限制在面板，Esc／关闭回到原行；保留筛选和页码；长错误不拉宽页面；不展示请求正文、密钥或 thinking 签名 |
| 设置与兼容 | 请求策略、数据保留、CPAMP 安装、兼容检查、存储恢复分区；常规保存与安装动作分离；安装预览用目标／变化／备份／重启条件表述；路径放高级区 | 保留天数从 0 改非零仍明确确认；单个兼容检查未知不显示全局健康；待写时间／最后成功／恢复文件与缺口可读；安装按钮禁用时说明原因 |
| 通用窗口 | 编辑字段分组、固定错误区和动作区；导入显示已选数量；危险操作说明影响；状态消息读屏可达 | 空值、失败、重试、运行中、取消都能恢复；键盘焦点返回触发处；不丢失未提交字段；不改变已有认证存储规则 |

模型搜索与状态筛选属于新增的前端交互，优先使用现有数据；若需增加 API、批量生成或后台任务，拆为后续功能。新详情面板仅改变展示，不改协议、持久化格式或证据判定规则。

## 6. 状态与数据场景

每个主要区域覆盖：首次加载、成功有数据、空数据、筛选无结果、请求失败、旧缓存、管理登录失效。加载中保留已有有效数据和布局；首次无数据的占位使用静态骨架，禁止刷新时整页闪空。

- 证据必须同时表达来源、结论和时间。“未知”“超过 24 小时”“暂时限流”“明确不在套餐”不能共用一个含糊状态。
- 额度刷新失败展示“上次观察时间＋刷新失败”；接收到同一旧快照不能把失败标记变回成功。
- 保存凭据后展示“已保存／宿主待确认”，只读诊断不得暗中触发生成或重装。
- 管理鉴权失败清除旧身份数据；模型测试 401／403 留在测试区域，不退出管理登录。
- 本地夹具包括 0／1／20 张凭据、0／3／100 个模型、相似长别名、完整长错误、缺少 cap、过期额度、部分检查失败、检查点恢复和持续待写。

## 8. 验收与交付物

### 浏览器与视觉

- 五页正常状态均提供 before／after；1280×900 与 390×844 两种视口、浅深两种主题，共 **20 组页面对照**。375px 另验导航、模型、日志详情和设置；1440px 验主布局；200% 缩放验主要流程。
- 对照说明逐项记录字体、边框、导航、标题、间距、列表、详情；区分“官网已核实”“为 Bridge 适配”“参照待补”，不宣称像素级复刻。
- 根页面 `scrollWidth <= clientWidth + 1`；必要的完整数据表只在有标签、可键盘操作的局部区域滚动。手机主要操作不依赖先横向拖到表格最右。
- 普通文字对比度至少 4.5:1，大字及必要控件／焦点边界至少 3:1；状态同时有文字。仅装饰性分隔线不套用控件对比度指标。
- Tab／Shift+Tab、Enter／Space、Esc、窗口焦点限制与返回、手机导航关闭全部通过。遵循减少动态效果设置；滚动、筛选和刷新不抢焦点。
- 五页及关键窗口无新增运行错误；复制摘要、登录、编辑、导入、只读刷新和安装预览均保留明确结果。真实生成测试使用模拟上游。

### 回归与打包

- `node --test tests/*.test.cjs`：保留诊断／模型证据的转义、延迟响应、鉴权隔离用例；只为新增焦点、筛选和窗口状态增加必要测试，不给每个颜色与间距写镜像断言。
- 在实际隔离 CPA 8.0.23 中验证内嵌控制台、管理鉴权与代理前缀，复用 `tests/cpa_diagnostics.py`、`tests/cpa_round2.py` 验证相关状态。纯视觉调整无需反复执行无关协议压力测试。
- 若修改 CPAMP 适配：运行 `apply.py --check` 与幂等校验、相关组件测试、type-check／生产构建，并核对内嵌页面和独立页面内容一致。
- Go／打包发生改动时补相应测试；发行级四平台门槛仍由 CI 执行。视觉验收与远端 CI 各自记录，不互相替代。

交付：页面代码、参照与差异表、完整截图索引、关键状态／键盘回归结果和 `docs/VALIDATION.md` 第三轮记录。截图先使用虚构数据，精选对照图可随文档提交；其余放测试产物。每个截图记录提交、视口、主题和场景。

完成定义：五页与通用窗口遵循同一套样式和状态规则；上述验收通过或有明确、可追踪的外部参照缺口。开发日估算不代表已经实施，也不包含真实上游验收、合并、发版或部署。
